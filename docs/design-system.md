# 1Day design system

状态：设计建议与后续实现约定。现有值来自 `Resources/Theme.swift`；标为“建议”的规则尚未全量应用。本文不是当前 App 或竞品的截图审计，也不表示 UI 已通过原生验收。

## 产品方向

**轻松拍下今天，和亲近的人一起留下短片。** 相机要直接，回看要安静，分享去向要清楚。保留奶油黄、圆润字体、人物头像和 Camera / Rooms 两个入口。既有经典蓝皮肤继续支持。

默认个人记录无需账号；房间协作才需要登录。每个界面突出一个主要动作，素材和人物占据视觉中心。主题、计划、心情为记录提供帮助，不增加完成压力。

## 参考清单

这是借鉴方向，不是对竞品当前版本功能或画面的逐项核验。当前网络代理拒绝 Setlog 的 App Store 查询与 Snapchat 官网访问；因此没有采用未经确认的截图、尺寸、颜色或转化指标。

| 参考 | 希望借鉴的方向 | 在 1Day 中的用法 |
| --- | --- | --- |
| Setlog（用户指定） | 围绕短片日记、日期与日常回看的体验做对照研究 | 检查“今天拍了什么”和按日期回看的清晰度；具体页面需后续核对 |
| [Snapchat](https://www.snapchat.com/) | 相机优先、拍摄后处理和选择去向的交互思路 | 打开相机即可记录，录完围绕预览完成保留、重拍、选择房间；具体版本未核验 |
| Apple Camera | 快门作为稳定的视觉与操作中心 | 录制时减少无关控件，切换镜头期间明确暂不可拍 |
| Apple Photos | 素材本身优先、浏览与编辑分开 | 房间和个人时间线优先显示片段；调整成片时才展开编辑选项 |
| Day One | 日记的日期感、安静的回看节奏 | 日期清楚、正文可读、空白日无惩罚提示；作为设计类比，未审计当前版本 |

## UI 优先级：十项

以下排序是产品判断，不是用户研究或性能测量结果。每项先核对既有能力，避免重复做入口。

| 顺序 | 建议 | 当前依据与状态 | 验收结果应是什么 |
| --- | --- | --- | --- |
| 1 · P0 | 保存和分享状态分开说明 | 拍摄已有房间选择；建议核对整条反馈链，未重写流程 | 只有本地写入成功才显示“已保存到我的片段”；只有服务端确认才显示“已分享到 {房间}” |
| 2 · P0 | 底栏支持大字体 | `FloatingTabBar` 固定字号且限制 Dynamic Type；待实现与原生验证 | 中英文、默认与最大字体、窄屏可读可点；内容末行不被底栏覆盖 |
| 3 · P0 | 让小字和状态文字可读 | 色值计算发现 `inkFaint` 在奶油底上不足 4.5:1；需逐个检查用途 | 所有需要阅读的普通文字达到 4.5:1；状态同时有文字/图标 |
| 4 · P1 | 拍摄页面围绕快门收敛 | 建议；保持已有录制方式与镜头能力 | 用户能辨别待拍、录制中、处理中；关键动作不被装饰分散 |
| 5 · P1 | 拍后预览突出保留和去向 | 建议；已有 `RoomSendList` 可复用 | 主动作与当前去向一致，重拍为次动作，失败不丢素材 |
| 6 · P1 | 房间卡片稳定展示人物、片段、状态 | 建议；成员与互动提前加载已有代码修改，原生待验 | 首屏能辨别谁拍了、内容是什么；某段加载失败不会挡住其他片段 |
| 7 · P1 | 个人回看保留日期线索 | Rooms 已有 `rooms-personal` 文字入口 | 找得到自己的记录，切换日期保留上下文，空白日仍可自然浏览 |
| 8 · P1 | 统一动作与点击面积 | `IconBubble` 已有 44pt 点击区；选择控件还需核对 | 一个主按钮，次操作样式稳定，交互目标至少 44×44pt，VoiceOver 读出选中状态 |
| 9 · P1 | 空、加载、失败各有明确反馈 | 建议；继续沿用已有重试与本地素材保护 | 空状态说明下一步；加载不清空已可见内容；失败可局部重试 |
| 10 · P2 | 收敛装饰与动效 | 底栏和时间线已修改为尊重 Reduce Motion，原生待验 | 开启减少动态效果后仍能看出选择；人物和视频比光晕、阴影更醒目 |

## 视觉规则与 tokens

颜色、字体、圆角的代码来源是 [Theme.swift](../ios/AISetlog/Resources/Theme.swift)，组件来源是 [OneDayControls.swift](../ios/AISetlog/Views/DesignSystem/OneDayControls.swift) 和 [OneDaySurfaces.swift](../ios/AISetlog/Views/DesignSystem/OneDaySurfaces.swift)。复用这些定义，不另建平行主题体系。

### 颜色

| 语义 | 奶油色浅色模式 | 奶油色深色模式 | 代码与用法 |
| --- | --- | --- | --- |
| 页面底色 | `#FFF8E8` | `#1E1912` | `OneDay.canvas` |
| 内容表面 | `#FFFFFF` | `#2A2219` | `OneDay.surface` |
| 次级表面 | `#FFF1CC` | `#3A2F22` | `OneDay.surfaceSoft` |
| 主文字 | `#3A2B1B` | `#F3E3C3` | `OneDay.ink` |
| 次级文字 | `#7A6650` | `#C9B593` | `OneDay.inkSoft` |
| 强调填充 | `#FFCB45` | `#FFCB45` | `Color.oneDayBrand`，用于主动作和选中态 |
| 强调上的文字 | `#3A2B1B` | `#3A2B1B` | `OneDay.onBrand`，黄色上用深色字 |
| 强调文字 | `#8A5A00` | `#FFD66B` | `OneDay.brandText`，用于链接、小标签 |

建议：不把浅黄色当小字颜色；人物身份色不复用为成功/失败状态。成功、待同步、失败都同时提供图标与文案；状态颜色需要分别检查浅深模式，不直接套用薄荷绿或浅粉色作为正文。

本轮按 WCAG 相对亮度公式计算的实色组合：深棕字/品牌黄 **9.01:1**；强调文字/白底 **5.93:1**；次级字/奶油底 **5.16:1**；`inkFaint #8F7C66`/奶油底 **3.79:1**；白字/经典蓝 `#1677FF` **4.10:1**。这些是实色计算，不涵盖渐变、透明叠加或视频背景，不能代替截图和交互验收。普通小字目标 4.5:1，大字与必要非文字图形按相应 3:1 标准检查；不能因为文字是时间戳就降低普通文字的对比度要求。

### 字体、布局与形状

| 项目 | 规则 | 状态 |
| --- | --- | --- |
| 字体 | 系统圆润字体，中文使用系统适配；沿用 `OneDay.Font` | 已有 |
| 标题 | `.title2`，默认约 22pt；标题之外避免满屏粗体 | 已有 token，层级为建议 |
| 正文/主动作 | `.body` / `.headline`，默认约 17pt | 已有 |
| 行标题/次操作 | `.callout` / `.subheadline`，默认约 16/15pt | 已有 |
| 元信息 | `.caption`，默认约 12pt，仍需可读；11pt 仅用于非关键短标记 | 已有 token，用途为建议 |
| 缩放 | 使用语义 text style；大字体时换行、增加高度或改变排列，保持完整标签 | 建议统一；底栏尚未满足 |
| 间距 | 4/8/12/16/20/24/32pt；页面边距 20pt，紧凑屏可 16pt，卡片内距优先 16 或 20pt | 建议，当前尚无统一 spacing token，`GlassCard` 默认仍为 18pt |
| 圆角 | 小容器 14pt、卡片 24pt、大预览容器 32pt；胶囊用于按钮和短选择项 | 现有 `OneDay.Radius` |
| 点击区 | 至少 44×44pt；图标可小于点击区；不要让相邻点击区互相覆盖 | `IconBubble` 已有，其余逐步核对 |
| 层级 | 页面底、内容表面、浮动操作三层；普通列表条目优先留白，减少层层卡片套卡片 | 建议 |
| 底栏避让 | 现有 clearance 为 78pt；大字体调整需同步所有页面的避让或改为实测尺寸 | 现状与后续约束，不只改字号 |

### 组件与反馈

| 组件/场景 | 规范 |
| --- | --- |
| 主按钮 | 复用 `PrimaryActionStyle`，一个主要动作；加载时保留按钮尺寸与动作说明，防重复提交 |
| 次按钮 | 复用 `SoftActionStyle`；删除/离开等破坏性动作使用明确文案与系统 destructive 角色 |
| 图标按钮 | 复用 `IconBubble`，提供双语无障碍标签；关闭、返回、更多各自含义明确 |
| 选择器 | 优先完善实际使用的选择控件；`PillSelector` 当前只有定义，无调用。文字和选中标记共同表示状态，并提供 selected trait；大字体不能依靠缩小文字解决 |
| 房间/片段卡片 | 预览为主，人物与日期为次，互动为第三层；加载不改变卡片身份；为失败片段保留重试位置 |
| 视频上的控件 | 复用 `overVideoControl` 与 scrim；检查纯白、纯黑和复杂画面上的可读性 |
| 空状态 | 一句说明与一个相关动作，例如“今天还没有片段 / 拍一段”；不制造连续打卡压力 |
| 动效 | 沿用 soft/pop/snap：spring response 分别 0.45/0.34/0.28 秒，它们不是固定播放时长；减少动态效果时停用装饰循环和大幅位移 |
| 触觉 | 有意义的选择或录制状态改变才反馈；不在加载、轮询、装饰动画时连续触发 |

拍后反馈建议：`保存中 / Saving…` → `已保存到我的片段 / Saved to My Clips`。若选择房间，再独立显示 `正在分享 / Sharing…` → `已分享到 {room} / Shared to {room}`；上传失败应说明 `已保存在本机，可重试分享 / Saved on this device. Retry sharing.`。这些是文案建议，需核对真实持久化和服务端确认边界后才接入 `Strings`，不能用一条 toast 掩盖部分成功。

## 如何应用与验证

1. 先以“拍摄 → 预览 → 保存/分享 → 房间或个人回看”一条旅程核对现状，再选择上表的一项改动。
2. 用 [dayday-design-system](../.agents/skills/dayday-design-system/SKILL.md) 约束组件与文案，用 [dayday-swift-performance](../.agents/skills/dayday-swift-performance/SKILL.md) 检查媒体任务、缓存和取消。
3. 用 [dayday-verify](../.agents/skills/dayday-verify/SKILL.md) 做相应检查。UI 验收需当前原生截图，覆盖中英文、两种皮肤、浅深模式、窄/宽屏、最大 Dynamic Type、Reduce Motion 和 VoiceOver；交互状态还需实际操作。
4. 每次只验证受影响的行为，不为颜色常量或页面快照数量而新增测试。新问题修复才补有意义的回归；视觉改动不能以语法检查替代验收。

已经应用的 Swift/性能 skills、头像缓存和动效修改见 [pstack 实施记录](plans/2026-11-13-pstack-ui-and-swift.md)。本次补充文档与设计 skill，没有将上述十项建议冒充为已实现；当前 Linux 环境没有运行 iOS 构建、原生 UI 或 Instruments。

后续代码进度：共用主次按钮已加入 Reduce Motion 支持；拍后房间选择列表已使用语义字号、两行标题和完整无障碍标签。均待原生验收；底栏的大字体布局仍待处理。

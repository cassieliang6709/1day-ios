1为什么是这一块

1Day 的承诺是「一天结束的时候你有一条片子」。前两轮把「怎么开始」和「怎么拍」修顺了，但用户真正会反复回到的是拍完之后——看自己刚拍的那两秒、翻今天已经有的几格、最后看成片。

这三屏目前的完成度差得很远：成片页（FilmView + FinalFilmTimeline）是照着设计系统认真做的；故事详情（StoryGridView / StoryTimelineView）中等；单条回看（ClipPreviewView，189 行）几乎没被设计过，是全 app 唯一一屏完全用 SwiftUI 默认控件、不在 OneDay 设计语言里的界面。

2现状：三屏体检

2.1 单条回看 ClipPreviewView — 最弱的一屏

① 视觉上不属于这个 app

白色导航栏、系统蓝的 Done、.buttonStyle(.bordered)、.font(.footnote) + .secondary。旁边每一屏都是 OneDayCanvas 渐变 + IconBubble + rounded 粗体 + GlassCard。从网格点进来的一瞬间像是切到了另一个 app。

② 「加字幕」按钮压在烧录进画面的文字上

add a caption 的胶囊按钮居中铺满整个播放区（.frame(maxWidth:.infinity,maxHeight:.infinity)），正好盖住 MomentStampOverlay 已经画在中间的 MOMENT 4。截图里两行字直接叠在一起。

③ 表情、时间、评论、重拍全在首屏之外

视频按 maxWidth: 340 撑满，375pt 宽的机器上竖屏视频高度约 600pt——点个表情都要先滚动。而评论输入框用 safeAreaInset 永久钉在底部，一条两秒的片子，屏幕被社交组件占掉一大块。

④ 看完这条，没有办法看下一条

只能 Done → 回网格 → 再点下一格。一天七格就是七次开关。这是回看体验里最贵的一次交互缺失。

⑤ 独自拍的故事里，社交组件是空的

challengeID != nil 就渲染表情栏和评论区。单人故事永远不会有别人来评论，但这两块一直占着位置。

2.2 故事详情 StoryGridView

⑥ 英文复数错误：Preview · 1 moments

截图实拍。文案函数没有分单复数。

⑦ 下一格的高亮是图标，不是画面

已拍的格子显示真实帧 + 时间戳 + 播放键，很好；未拍的格子只有一个题目图标。当前该拍的那格（Morning light）只是加了个实线边框，和「已拍」的视觉重量差太多。

2.3 成片 FilmView — 基本健康

分阶段的生成动画、渲染失败有明确出口和重试、renderRevision 把所有会烧进画面的字段都算进了失效判断（这个做得很对）、「调整」表单克制。这一屏这轮基本不动，只补两处：保存到相册后没有触觉反馈；AdjustFilmSheet 是全 app 另一处没上设计系统的地方，但它是设置表单，按注释说的「不打扮」是合理的，保留。

3P0：单条回看重做

目标一句话：让它看起来像 1Day，并且能一条条往下翻。

布局

  • 整屏 OneDayCanvas 背景，去掉 NavigationStack 的白条，改用左上 IconBubble 关闭 —— 和 FilmView 一致。
  • 视频不再放进 ScrollView，改为占据首屏主体；表情栏浮在视频下沿之上，永远可见，不需要滚动。
  • 时间戳从底部的 .footnote 挪到视频左上角的胶囊里 —— 网格缩略图上已经是这个位置，两处一致。
  • 评论区收进一个「N 条评论」的按钮，点开才是 sheet。评论输入框不再常驻。

翻页

  • 改成 TabView(.page)，左右滑在同一个故事的已拍片段之间移动。
  • 需要新的 Presentation 类型 ClipDeck：给定故事 + 当前 day + 我的 id，算出可翻的片子顺序和当前位置。纯逻辑、可测、不读时钟。

字幕编辑

  • 「加字幕」按钮不再铺满播放区。没有字幕时显示在视频下方的操作行里；已有字幕时点字幕本身进入编辑。
  • 修掉和 MomentStampOverlay 的重叠。

重拍

  • 从底部的大 .bordered 按钮降级到右上角 ... 菜单里。它是这屏最有破坏性的操作，不该是最显眼的控件。

单人故事

  • 表情栏和评论区的条件从 challengeID != nil 改成 challenge.isShared。

4P1：详情页与成片收尾

  • 修 Preview · 1 moments 的复数。补一条本地化测试 —— 现有的 LocalizationTests 没有覆盖任何带数量的英文文案。
  • 网格里「该你拍的那格」给出和已拍格子相当的视觉重量（虚线 → 实心 + 主色）。
  • 保存到相册成功后加触觉反馈。

5P2：轻美颜

先说代价：这不是加一个滤镜，是重写取景管线

ClipRecorder（312 行）现在用 AVCaptureMovieFileOutput + AVCaptureVideoPreviewLayer。这两个都是硬件直通——预览层是摄像头到屏幕的直连，文件输出是硬件直接编码写盘，中间没有任何地方能拿到每一帧。

要加美颜必须换成：AVCaptureVideoDataOutput + AVCaptureAudioDataOutput → 每帧过滤镜 → MTKView 预览 → AVAssetWriter 手写音视频轨。难的不是滤镜，是音画同步、旋转方向、来电打断时 writer 的状态机——全是 MovieFileOutput 现在替我们扛着的。

技术选型：Core Image，不引第三方

调研了三个开源框架：MetalPetal（Metal / MIT / 在维护 / 有现成的 MTIHighPassSkinSmoothingFilter）、GPUPixel（C++ 跨平台 / 磨皮瘦脸都有 / 但带预编译人脸模型二进制，上架隐私清单要额外确认）、GPUImage3（2021 年后停更，排除）。

结论是先不引：贵的那部分（管线重写）用不用框架都一样贵，装依赖一分钟也省不了。而目标是「别看着自己尴尬」，不是抖音级美颜，系统自带的 Core Image 够用：

CIGaussianBlur + 软光混合   → 磨皮
CIColorControls             → 提亮、降饱和
CITemperatureAndTint        → 加点暖

零依赖、零授权、不增加包体积。真觉得磨皮质感不够，再换 MetalPetal——管线是现成的，换的只是中间一段。

产品决定（已定）

  • 默认关。1Day 的前提是记录真实的一天，默认开美颜和这个前提打架。
  • 用户可开，强度可调，选择记住。
  • 不做瘦脸大眼。那需要人脸关键点，而且对一个讲「真实」的 app 是另一个方向的产品决定。

没解决的疑问

用户原话是「避免大家看自己尴尬」。如果尴尬主要发生在回放而不是拍摄，那滤镜是在错的地方使劲，成本却是整个管线重写。P0 做完之后重新评估一次再动手。

7不做什么

  • 不重做 FilmView。它是目前质量最高的一屏。
  • 不做视频剪辑（裁剪、调速、配乐）。1Day 的卖点是「不用剪」。
  • 不改 AdjustFilmSheet 的表单外观。它是设置，不是内容。
  • 不碰 CloudKit。schema 部署是独立的发布阻塞项，不混进这一轮。

遗留：多人拍摄暂时无法本地测试

示范房间这轮已经拆掉（用户要求）。在 CloudKit schema 部署到 Production 之前，多人相关的改动只能靠单测覆盖，没有可点的验证路径。

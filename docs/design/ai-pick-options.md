# AI 挑片：要 Cassie 定的三件事

「随机挑」现在在本机做：打乱最近 7 天的片段，跳过太暗、太糊的，凑够 30 秒（`cc6b475`、`cfd2329`）。
AI 挑要在这个基础上更进一步：挑出值得看的几段、排好顺序，最好再起个标题。

## 1. 画面要不要离开手机

| 方案 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| **A 只传文字（推荐）** | 手机上用 Apple Vision 给每段打标签（有没有人脸、场景是什么、画面里的文字、亮度、清晰度），只把「时间 + 标签」发给现有的 suggest-prompts 那种 Worker，让文本模型挑段落、排顺序、起标题 | 画面不出手机；沿用现有 Worker 和 DeepSeek key，不加新供应商；文本请求很便宜 | 模型看不到画面，只能靠标签判断，「哪段好看」判断得比较粗 |
| **B 传缩略图** | 每段取一帧，压到约 256px 的 JPEG，经新的 Worker 发给能看图的模型 | 效果最好，能看懂画面内容 | 画面会离开手机，隐私政策要改；按图片计费，比纯文字贵，具体价格要查当时的价目表 |
| **C 先不做 AI** | 继续把本机挑做强：把几乎一样的片段只留一段，优先挑有人脸、有动作的 | 不上传、不花钱 | 不会起标题，排顺序只能按时间 |

## 2. 用哪个模型

- 方案 A：沿用 suggest-prompts 的 DeepSeek，只需要新加一个接口。
- 方案 B：要换成能看图的模型，比如 Claude Haiku。需要新的 API key 和一个新 Worker。

## 3. 用量上限

现有 Worker 已经按设备限流，超出时返回 `429`。AI 挑也需要一个上限，例如每台设备每天 N 次。超出后退回本机的随机挑，不弹错误。

## 我的建议

先做 A。它不改隐私政策，也不加新供应商，花的钱可以忽略。用一段时间后如果觉得挑得不准，再考虑 B。

工作量估计：A 约 1 天（手机端打标签约半天，Worker 接口和接入约半天）；B 约 1.5 天，另外要改隐私政策。

1Day 技术文档 — 系统是怎么搭的

一天（或一周）拍几个两秒的片段，晚上自动拼成一条小片；也可以拉朋友进同一个房间，各拍各的，拼在一起。这份文档写的是这件事在代码里是怎么成立的：分层、数据落在哪、CloudKit 怎么同步、视频管线为什么长这样，以及哪些地方是踩过坑才变成现在这个样子的。

01一句话和一张图

一个 Challenge（一条故事）有 N 个 DayCard（槽位）。每个槽位录一段短视频，文件落在本地磁盘，卡片上只存文件名。VideoStitcher 把这些片段按顺序拼成一条片子。如果这条故事带 roomCode，它同时是一个 CloudKit 房间——每个人的片段上传到公共库，别人拉下来，同一天的几个人拼成一格一格的画面。

没有后端服务器。除了一个只负责调 LLM 的 Cloudflare Worker，所有"服务端"能力都是 CloudKit 提供的。

02分层，和唯一一条被 CI 盯着的铁律

层职责约束
Models/纯数据结构，Codable，向后兼容旧存档不能出现 Strings.——展示文案属于 Presentation。CI 用 grep 直接卡住
Presentation/把 Model 变成"该显示什么"的纯计算不 import SwiftUI，不读 .now（时间靠参数传进来），因此可以全量单测
Services/所有 I/O：磁盘、相机、CloudKit、通知、网络先定协议再写实现，测试可替换
Views/SwiftUI，只读 store、只调 store自己不碰 FileManager / CloudKit

为什么 Presentation 不许读 .now

"今天是第几天""这个槽位是过去、今天还是将来"这类判断，如果直接读系统时间，测试就只能在特定时刻通过。把当前时间作为参数传进去之后，StorySchedule、RoomProgress、StoryTimeline 这些东西可以在任意假时间下断言，跨午夜、跨时区的行为才有人验证过。

Challenge 里大量字段是 Optional 且带注释写着"nil 表示旧存档"——mode、clipLength、orientation、roomCode、ownerID。这不是懒，是因为数据是 JSON 存在 UserDefaults 里的：老用户的存档必须能被新版本解码。对应地每个可选字段都有一个 resolvedXxx 兜底。

03数据落在哪

位置内容
UserDefaults challenges.v2全部故事（JSON 编码的 [Challenge]），含卡片、表情、评论
UserDefaults customTemplates.v1用户自建模板
UserDefaults onboarding.completed.v1首次启动引导是否走完
UserDefaults appLanguage / appAppearance语言、深浅色
Documents/clips/<challengeUUID>/day<N>.mov我自己录的片段
Documents/clips/room_<CODE>/从房间下载的别人的片段（缓存，可丢）

视频从不进 UserDefaults，卡片上只存文件名。ClipFileStore 是唯一碰 FileManager 的地方；ChallengeRepository 是唯一碰 UserDefaults 的地方。两个都是协议，注释里写明了"今天 UserDefaults，明天 SwiftData，换实现就行"。

v1 → v2 的迁移还留在 UserDefaultsChallengeRepository.migrateLegacyIfNeeded()：v1 只有一条无 id 的 challenge，片段散在 clips/ 根目录下。迁移会补一个 UUID、把文件挪进以它命名的子目录、写回 v2、删掉旧 key。

04共享房间：CloudKit

用的是 公共数据库（public DB），不是共享库。理由很实际：一个 6 位邀请码谁拿到谁能进，不需要 CKShare 那一套邀请链路；代价是记录对整个容器公开，所以里面不放任何私密字段。

四种记录

recordTyperecordName说明
Room房间码本身，如 K7M2XQ标题、起始日、模式、片长、朝向、moment 列表、房主
Clip<code>_<authorID>_day<N>视频 CKAsset + 作者 + 字幕。名字可推导 ⇒ 重录就是覆盖同一条，不会产生第二份
Reaction由 code/day/作者/目标/emoji 拼出append-only，同一个人对同一条按两次不会变成两条
Comment本地生成的 UUID本地和远端用同一个 id，两边各自去重

幂等是设计出来的，不是重试出来的

所有写操作的 record name 都能从"谁 + 哪个房间 + 哪一天 + 什么"推导出来。所以重试、双击、第二台设备重放同一个写入，落到的都是同一条记录。删除也不用先查询——直接按推导出的 id 删（见 deleteMyRoomData）。

同步是本地优先的

ChallengeStore.recordedClips(for:) 里有一段值得单独讲：一个房间的片段列表 = 远端全部 + 我自己还没上传成功的那些。曾经这里只返回远端列表，结果是离线拍的一条会从房间、首页卡片和计数里消失，重启才回来。现在本地那一半不是"没同步时的兜底"，而是那条片段唯一的记录。

表情和评论的合并同理：远端是真相，但要跟我刚点下去、还没被回传的那些取并集，否则手指刚离开屏幕表情就闪一下没了。

登出要清房间缓存

缓存是按 author id 存的，而登出会改变"我是谁"。不清的话，我自己上传的片段会变成别人的：名单里还列着我，每个空槽写着"在等 <我自己的名字>"，页头把我的镜头署了个陌生人的名。所以 signOut() 会逐个房间 clearRoom()；故事本身不动，丢的只是别人作品的借来副本。

删除账号

deleteAccountAndAllData() 是 App Store 审核 5.1.1(v) 要求的：创建账号的 app 必须能删账号，登出不算。实现上先按可推导 id 删云端我写过的一切，再无条件清本地——云端失败也照删本地，因为人家说的是"让我消失"，不能因为一次网络错误就把人留在已登录状态。

05视频管线

ClipRecorder (AVCaptureSession)
   └→ 临时文件
        └→ ClipFileStore.storeClip()  →  Documents/clips/<uuid>/dayN.mov
             ├→ （共享房间）RoomSyncService.uploadClip() → CKAsset
             └→ VideoStitcher.stitch(clips:options:) → 成片 .mov

两种排布

  • .sequential——一条接一条，带交叉淡入（默认 0.35s）。个人故事走这条。
  • .friendsTogether——同一天的多个人同时播，按 grid(for:in:) 算行列铺成格子。房间的成片走这条。

叠加层只在真机上有

标题卡、DAY N 字幕、emoji 贴纸、评论气泡、时间戳、水印，全部通过 AVVideoCompositionCoreAnimationTool 挂 CALayer 实现，而这一套在模拟器上导不出来。所以 VideoStitcher 里有三处 #if !targetEnvironment(simulator) 把它们整段编译掉。

后果要记住：成片的任何叠加效果，模拟器截图证明不了。改动这块只能在真机上验。模拟器上跑出来的是一条没有任何文字的干净片子，看起来"正常"，其实少了一半东西。

06柔和一点（GentleLook）

已在 main 来自 PR #8 / #10，2026-09-03 合入。

GentleLook 是个纯值类型：三个 0…1 的旋钮——smoothing（细腻）、brightness（提亮）、warmth（暖调）。它自己不认识 CoreImage，只负责把三个数字推导成一组有上限的参数：

推导出的量上限为什么是这个上限
blurRadius8.0模糊半径
blurOpacity0.35把模糊直接混进去的比例。这一档故意压低——它才是让脸变塑料的那个
softLightOpacity0.55柔光叠加，只加光不动边缘，效果的大头在这
brightnessDelta / saturation+0.06 / −0.08提亮的同时降饱和，否则皮肤发橙
temperature / tint6500→5200K / +8暖 = 色温降低，写反了"暖阳"会变蓝

一个像素测试逼出来的设计

最早只有柔光一条路径。像素测试（32×32 棋盘格 + 软件 CIContext）跑出来对比度是 0.0925，没低过要求的 0.0909（原始对比度的 0.9 倍）——因为柔光叠模糊会保住底层结构，"细腻"其实没磨到任何东西。于是拆成两条独立上限的通道：一条真的把模糊混进去（低上限），一条只加光（高上限）。这个 bug 靠看模拟器截图是发现不了的。

为什么回看和导出是两条路

一个 asset 只能有一个 AVVideoComposition。VideoStitcher 已经手写了一整套 instructions（交叉淡入、格子排布）外加 animationTool；而 AVMutableVideoComposition(asset:applyingCIFiltersWithHandler:) 会自己生成一套 instructions。两者不能共存。所以：

  • 回看：没有叠加层，直接把 filter composition 挂到 AVPlayerItem.videoComposition。
  • 导出：先逐条把片段滤成临时文件，再拿滤过的文件去拼。拼完删临时文件。某一条滤失败不影响成片——那条以原样进片子。

AVPlayerLooper 的坑

AVPlayerLooper 每一轮循环都会复制模板 item。也就是说 composition 必须在第一帧之前就建好，否则第一遍有滤镜、之后每一遍都没有。LoopingPlayerLayerView 因此是先 await 建好 composition，再开始播——而不是先播再挂。

存两个 key

gentleLook.v1 存当前的样子，gentleLook.sticky.v1 存"以后都这样看"。启动时 AISetlogApp.init() 调纯函数 GentleLook.onLaunch(stored:sticky:)：没勾选就还原成"原样"。在任何 view 读到这个 key 之前做完，免得闪一帧昨天的设置。

07提示词服务：一个只做一件事的 Worker

workers/suggest-prompts，Cloudflare Worker，216 行。输入一句"今天要搬家"，输出七个值得对着拍的瞬间。模型是 DeepSeek，API key 只在服务端——打进 app 里的 key 就是别人会替你花的钱。

它是加速器，不是关卡

PromptSuggestionService 的每一种失败都是静默的，用户被放回原来那个可以手填的列表。三种错误（malformed / rateLimited / unavailable）在 UI 上不区分，因为对用户来说没区别：他要做的事本来就还能做。超时 20 秒。

08通知

  • ReminderService——本地通知，晚间提醒。时间在设置里可调，每次 challenges 变化时 reconcile 一次。
  • SharedActivityNotificationService——CloudKit 订阅，朋友上传时推送。可以按房间静音（NotificationPreferences.mutedRoomCodes），也可以选择不显示朋友名字。

两者都在 app 变为 active 时重新对账，因为通知授权和房间列表都可能在别处被改过。

09双语

中英文不走 .strings 文件，走一个 Strings 枚举，每个条目是个计算属性：

static var lookWarm: String { lang == .chinese ? "暖阳" : "Warm" }

好处是加一句话只改一个文件、编译期就知道漏没漏；.lproj 只留给系统权限弹窗那几句（InfoPlist.strings）。语言可以在设置里强制，不跟随系统。

CI 上跑不了的那四套

四套 CloudKit 集成测试在 CI 里是被 -skip-testing: 跳掉的。它们本来就会在没登 iCloud 的模拟器上 XCTSkip，但 CI 用 CODE_SIGNING_ALLOWED=NO 构建，没有 iCloud entitlement——对一个没授权的 container 调 accountStatus() 会直接打死 test host，进程都没了，谈不上 skip。

所以这块覆盖率只存在于本机：要验它们，得在一台登了 iCloud 的模拟器上跑完整套。这是真实的覆盖缺口，不是被掩盖的失败。

CI

.github/workflows/ios-tests.yml，GitHub Actions macos-15。这份 workflow 在 2026-09-02 修过一次大的，因为 runner 镜像的漂移让它整整两周没绿过一次：

  1. 原来钉在 Xcode 16.2。镜像留着这个 Xcode 却删掉了 iOS 18.2 的模拟器 runtime，actool 拿不到对得上的 SDK 就把整个 build 判失败——报的是 Assets.xcassets: error:，看起来像资源问题。改成 Xcode 26.2（镜像上的模拟器现在全是 iOS 26）。
  2. 然后是"找不到设备"。runner 一台 iOS 模拟器都不预建，靠写死设备型号名让 xcodebuild 现场造一台——而这件事只在某些 job 上成功。现在的做法是按 SDK 版本挑 runtime、自己 simctl create 再 boot，并在这一步先确认 xcodebuild 看得见它，不然就在这里失败，而不是等测试跑起来才报一个含糊的错。
  3. 然后才第一次看到真正的测试结果：上面第 10 节说的那四套 CloudKit 测试把 test host 打死了。跳过。

另外 workflow 里那条 grep -rn "Strings\." AISetlog/Models/ 就是第 2 节那条铁律的执行者。

发布

Archive → -exportArchive（method: app-store-connect，配 -allowProvisioningUpdates 自动建发行证书）→ Organizer 上传 TestFlight。

上线前必须做的一件事

CloudKit 的 schema 要部署到 Production（Dashboard → Deploy Schema Changes）。开发库上跑得好好的房间和邀请码，在正式包里会直接失败，因为 Production 那边根本没有这些 record type 和可查询索引。一个人用的部分（拍摄、回看、成片）不受影响。

相关的错误码已经在代码里翻译过了：字段还没标成 queryable 时 CloudKit 报 invalidArguments，CloudKitService 把它转成 fieldNotQueryable，界面上说的是"索引还在部署中"。

12已知的坑

阻塞上线

  • CloudKit Production schema 未部署 ⇒ 正式包里共享房间必挂

覆盖缺口

  • 四套 CloudKit 集成测试只能本机跑
  • 成片叠加层（字幕/贴纸/水印）模拟器上编译掉了，只能真机验

零碎的债

  • AvatarBadge 目前没人用了（#11 之后）
  • Strings.makeTheFilm 无引用，留着怕有在飞的分支要用
  • 时间轴的时间戳印在缩略图里，不在左侧轴上——PRD 里写过要改，没动
  • 字幕编辑目前只改本地，房间同步要等下一次片段上传才带过去
  • StoryGridView 和 StoryTimelineView 有重叠，合并过一次评估，决定不合

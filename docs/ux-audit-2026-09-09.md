# 1Day 用户旅程 UX 审计报告

日期：2026-09-09
范围：`ios/AISetlog` 全部视图层 + 本地化文案 + 关键服务（ChallengeStore / ClipRecorder / ReminderService），只读审计，未改动任何代码。
不含以下已知另案处理项：跨设备邀请码加入失败、7 日模板封面黑图、快门按钮改品牌蓝。

---

## 旅程地图总览

```
首次打开
  └─ FirstRunOnboardingView（承诺页：3 个 2 秒瞬间 → 1 支短片）
       ├─ 「开始我的第一支片」→ createQuickStart() → 直接落到故事页（3 个待拍瞬间）
       └─ 「有邀请码？加入朋友」→ JoinInviteSheet →（未登录先过 SignInView）→ 房间故事页

日常回路（RootShellView：计划 / 拍摄 两个 surface）
  ├─ 计划页 PlansHomeView
  │    ├─ Hero StoryCard「继续今天的故事」→ 直接开相机（默认第一个没人拍的瞬间）
  │    ├─ header：头像=设置 / person.2.badge.plus=加入房间 / ＋=新建故事
  │    └─ 时间线列表 → StoryTimelineView（故事页）
  │         ├─ 「还没拍的」行 → RecordClipView（拍 → 回看 → 使用/重拍）
  │         ├─ 「拍过的」网格 → ClipDeckReview（左右滑）/ StitchedMomentPreview（房间）
  │         ├─ 全部拍满 → FilmReadyCard → FilmView（合成 → 保存/分享/调整）
  │         └─ ⋯ 菜单：预览 / 编辑计划 / 删除或退出房间
  └─ 拍摄 tab（自由拍）→ 录完「存入计划」选择器，或「先存起来」进草稿箱

次日回归
  └─ 晚间提醒通知 → 点按直达相机；或 hero 卡自动切换为「接着拍」
```

整体信息架构是清晰的：单 hero + 时间线、两步 composer、拍摄-回看-归档三段式。问题集中在**三个不可逆/无出口的坑**（丢片段、权限死路、无确认删除）和**加入房间链路的可发现性与中断恢复**。

## 旅程 1：首次打开 → 理解产品 → 创建第一个故事

### 1.1 onboarding 没有「先随便看看」的出口 🔵

- **现状**：首屏只有「开始我的第一支片」和「有邀请码？加入朋友」两个按钮（`Views/Home/FirstRunOnboardingView.swift:57-71`）。
- **问题**：想先逛逛的用户被迫二选一。实际上点「加入朋友」再取消可以逃逸到主页空态，但这条路径没有任何提示，属于意外出口而非设计出口。
- **建议**：在 Join 按钮下方加一行低调的 text button「先随便看看」（复用 `OneDay.inkFaint` 样式），直接 `hasCompletedOnboarding = true` 落到主页空态。主页空态本身（吉祥物 + 「开始今天的故事」）已经是很好的兜底页。

### 1.2 onboarding 的「3 个瞬间」承诺与 composer 默认不一致 🔵

- **现状**：onboarding 写死「3 个两秒瞬间 → 1 支短片」（`Localization.swift:340-345`），`createQuickStart()` 确实建 3 瞬间 × 2 秒（`Services/ChallengeStore.swift:149-156`）。但用户之后自己进 composer 时，默认选中的是 7 瞬间模板。
- **问题**：不是错误，但「原来不止 3 个」的期望差可能让第二个故事的创建显得变重了。
- **建议**：低优先。可在 composer 心情步骤的副标题里带一句「3 个起拍，想拍几个都行」，把数量从承诺变成范围。

## 旅程 2：创建故事（心情 → 设置 → 瞬间 → 标题 → 创建）

两步流程本身顺畅：标题随模板自动填充直到用户手动改过（`StoryComposerView.swift:317-327`）、错误提示贴着按钮（`:166-198`）、瞬间可增删改。一个硬伤：

### 2.1 「七个瞬间」标题是硬编码的 🟡

- **现状**：设置步骤的瞬间区标题 `SectionLabel(text: Strings.theMoments)`（`Views/Compose/ComposerSteps.swift:530`），而 `Strings.theMoments` 中文写死「七个瞬间」（`Localization.swift:1092`）。
- **问题**：quickStart 故事只有 3 个瞬间，自建故事可以是 2–12 个，标题全都显示「七个瞬间」。这是用户一眼可见的事实错误，直接损害对页面的信任。
- **建议**：改成 `Strings.theMoments(count)`：「3 个瞬间」/「The moments · 3」。改动极小。

### 2.2 「自己写题目」入口沉底 🔵

- **现状**：自建题目入口在心情步骤模板网格之下（`ComposerSteps.swift:97-128`），模板一多就要滚到底才能看到。
- **问题**：想写自己题目的用户会先翻一遍模板墙，可能以为只能选模板。
- **建议**：把它提到 pill selector 正下方、模板区之前；样式不变，只调顺序。

## 旅程 3：创建共享房间（登录门槛 → 创建 → 拿到/分享邀请码）

### 3.1 房间建成后缺少「现在把码发出去」的引导时刻 🟡

- **现状**：`createSharedRoom()` 成功后 dismiss composer 直接落到故事页（`StoryComposerView.swift:247-266` → `PlansHomeView.swift:48-50`）。邀请码的露出只有两处：header 里一个 12pt 小 pill（`Views/Timeline/TimelineHeader.swift:61-99`）和导航栏的「邀请」ShareLink（`Views/Timeline/StoryTimelineView.swift:284-295`）。
- **问题**：composer 里的 `roomExplainer`（`ComposerSteps.swift:647-658`）事前说过「创建后房间里先只有你」，但创建成功这一刻——用户最愿意分享的时刻——app 反而安静了。用户要自己在页面上发现那个小 pill。
- **建议**：房间创建成功且是本地第一次建房间时，落到故事页后一次性弹出分享面板（直接上 ShareLink 的 activity sheet，带「邀请码 ABC123」标题），或在 invite pill 上加一次性脉冲高亮 + coach mark「点这里发给朋友」。一次性即可，不要常驻。

### 3.2 取消登录后流程的回程没有说明 🔵

- **现状**：未登录点「创建房间」→ SignInView（`StoryComposerView.swift:231-232`），点「先不了」（`Views/Settings/SignInView.swift:74`）回到 composer，`withFriends` 仍为 true。
- **问题**：状态没丢（这点比 join 链路好），但用户可能没意识到「房间没建成」，再点一次「创建房间」又弹登录，形成循环困惑。
- **建议**：登录 sheet 取消后，在 composer footer 错误区（已有机制）给一行非错误色提示：「创建房间需要登录，也可以切回『自己来』。」

## 旅程 4：加入房间（入口在哪？三条路径都顺吗？）

### 4.1 常驻入口可发现性差：只有一个 36pt 无文字图标 🟡（本旅程最重）

- **现状**：onboarding 之后，加入房间的唯一常驻入口是主页 header 的 `person.2.badge.plus` 图标（`Views/Plans/PlansHomeView.swift:169-173`），36pt、无文字、混在设置头像和新建按钮之间。空态卡（`PlansHomeView.swift:269-291`）和「今天还没开始」卡（`:248-266`）都只有「创建」按钮，没有 join 入口。
- **问题**：朋友发来邀请码的用户，装上 app、过了 onboarding 之后，要在三个图标里猜哪个是「输入邀请码」。`person.2.badge.plus` 语义更接近「加好友」而非「输入码」。注意：文案其实都写好了但没接上——`haveInviteCode`（`Localization.swift:336`）、`joinFriendsWithCode`（`:416-418`）、`homeChoiceHint`（`:419-423`）三条字符串在全工程无调用方。
- **建议**：
  1. 空态卡与 startTodayCard 各加一个次级文字按钮「有邀请码？加入朋友」（复用 onboarding 的次按钮样式），直接打开 JoinInviteSheet；
  2. header 图标保留，但空态期的主页让「加入」成为与「创建」并列的可见选项。这正好把那三条闲置文案用起来。

### 4.2 取消登录 → join 静默中断，邀请码丢失 🟡

- **现状**：JoinInviteSheet 点「加入」先关 sheet 再 `startJoin`（`PlansHomeView.swift:64-67`）；未登录时把动作挂到 `afterSignIn` 弹 SignInView（`:424-440`）。用户在 SignInView 点「先不了」→ sheet 关闭、`afterSignIn` 清空（`:72-78`）——输入的 6 位码随 JoinInviteSheet 一起没了，用户要重新打开、重新输一遍。深链接路径同样：`onOpenURL` 解析后（`App/AISetlogApp.swift:97-101`）走同一个 `startJoin`，取消登录后码同样消失。
- **问题**：登录门槛挡住的恰恰是「被朋友拉来、最没耐心的新用户」。每多一次重输，流失一分。
- **建议**：登录取消时把未完成的 code 保存下来并重新打开 JoinInviteSheet（码已填好），加一行「登录后点加入就行」。深链接路径同理：`pendingJoinCode` 在登录取消时不要丢弃，回存待下次。

### 4.3 「粘贴」无码时静默无反应 🔵

- **现状**：`JoinInviteSheet.swift:36-41`，剪贴板里没有可提取的邀请码时，按钮什么都不做。
- **建议**：失败时给一个轻提示（复用录制页的 toast 模式）：「剪贴板里没有找到邀请码」。

### 4.4 按钮文案「加入今日房间」对 7 日房间不准确 🔵

- **现状**：`Strings.joinRoomButton` = 「加入今日房间」（`Localization.swift:429`），显示在 JoinInviteSheet 主按钮上。
- **建议**：改「加入房间」。一个词的改动，消掉对 7 日挑战的语义错误。

### 4.5 加入中的全屏 spinner 无取消、无超时 🔵

- **现状**：`joining` 时全屏 `ProgressView` 遮罩（`PlansHomeView.swift:130-137`），只有 Task 结束才解除（`:428-437`）。网络挂起时用户只能杀 app。（跨设备 join 失败本身另案处理。）
- **建议**：遮罩上加「取消」按钮 cancel 掉 Task；或给 fetch 加超时并落到现有 `errorText` alert。

### 4.6 分享文案依赖 `oneday://` 自定义 scheme 🔵

- **现状**：分享文案尾部带 `oneday://join?code=XXXXXX`（`Localization.swift:550-559`）。微信等 App 内自定义 scheme 不可点；接收方未装 1Day 时链接无回退。
- **建议**：短期——分享文案里把明文路径写全：「邀请码 ABC123（打开 1Day，首页右上角输入）」，不依赖链接可点。长期——考虑 universal link + App Store 回退。

## 旅程 5：录制片段（找入口 → 按提示拍 → 重拍/保留）

### 5.1 回看页点 X = 已拍片段无声丢弃 🔴（全报告最重的坑之一）

- **现状**：`RecordClipView` 的 `topBar` 在任何状态（包括已拍完、正在回看的 review 状态）左上角都是「X → dismiss()」（`Views/Record/RecordClipView.swift:515-524`）。dismiss 后 `onDisappear` 触发 `recorder.teardown()`，临时文件直接作废，**没有任何确认**。
- **问题**：自由拍摄 tab 有 `UnfiledClipGuard` 兜底（`Views/RootShellView.swift:96-110`，代码注释明确写着这正是为了防止「丢片段是悄悄发生的」），但从故事页/主页打开的按瞬间录制 modal 路径没有同样的保护——同一个 bug 的另一半还开着。用户拍好一条 2 秒片段，习惯性点 X 关掉相机，片段就没了，而且没有任何迹象表明它消失过。
- **建议**：把 guard 延伸到 modal 路径：`recorder.clipURL != nil` 时，X 改为弹 `confirmationDialog`（保留为草稿 / 丢弃 / 取消），与自由拍摄的文案 `keepClipQuestion` / `keepClip` / `discardClip`（`Localization.swift:618-620`）完全复用。

### 5.2 相机权限被拒后是死循环 🔴

- **现状**：`ClipRecorder.configure()` 里 `AVCaptureDevice.requestAccess` 返回 false → `state = .unavailable`（`Services/Media/ClipRecorder.swift:52-56`）。`unavailableView` 只有「重新打开相机」一个按钮（`RecordClipView.swift:432-445`）。iOS 对已 denied 的权限不会再弹系统框，重试永远返回 false。
- **问题**：第一次误点「不允许」的用户，永远停在「相机不可用 / 重新打开相机」的循环里，app 从头到尾没告诉他要去系统设置。对相机为核心功能的 app，这是首次使用的致命断点。
- **建议**：检测 `AVCaptureDevice.authorizationStatus == .denied` 时，把界面换成「需要在系统设置里允许相机权限」+「打开设置」按钮（`UIApplication.openSettingsURLString`）。通知权限被拒时已有同款模式可抄（`Views/Settings/SettingsView.swift:120-129`）。

### 5.3 两个相机入口并存且没有任何解释 🟡

- **现状**：底部浮动胶囊两个 tab：「计划 / 拍摄」（`RootShellView.swift:63-76`）。「拍摄」tab 是自由拍，录完要走「存入计划」选择器（`RecordClipView.swift:336-342`）或存草稿；而真正的故事拍摄入口在 hero 卡「继续今天的故事」和故事页的行里。
- **问题**：有故事在拍的用户点「拍摄」tab，录完一条，才被问「把这段视频存入…」——这时他才知道这台相机不是给故事拍的。「为什么有两个相机」没有任何 UI 解释。
- **建议**：自由拍摄页在取景框下方加一行常驻小字（未录制时）：「随手拍的一段，拍完再决定放进哪个故事」；或者反过来，当有进行中的故事时，相机 tab 顶部给一个「直接拍《我的一天》的下一个瞬间 →」的快捷条。二选一即可，前者改动最小。

### 5.4 「重拍」静默覆盖旧片段 🟡

- **现状**：片段回看页（`ClipPreviewView`）的「重拍」chip（`Views/Record/ClipPreviewView.swift:338`）→ 重录 → 「使用这段」→ `saveClip` 直接覆盖同一天的文件（`Services/ChallengeStore.swift:391-418`），全程无提示。
- **问题**：覆盖本身合理（重拍的本意），但「原来那条会没」这个事实用户是事后才发现的。2 秒片段的沉没成本低，所以不到 🔴，但一次「替换前确认」成本很低。
- **建议**：从 ClipPreviewView 进入的重拍，在 review 页把「使用这段」改成「替换原片段」（仅这一入口改文案即可，行为不变）；或者在第一次覆盖时弹一次性确认。

### 5.5 time-only 故事的录制页顶栏显示「第 1 天」 🔵

- **现状**：time-only 故事 `slotTitle = nil`，`RecordClipView` 回退显示 `Strings.dayN(day)`（`RecordClipView.swift:75-77`）→ 一日故事显示「第 1 天」。
- **建议**：time-only 时顶栏用 `Strings.timeOnlyMoment`（「拍下这一刻」，`Localization.swift:1049-1051`），语义和文案都是现成的。

### 5.6 字幕功能可发现性弱 🔵

- **现状**：字幕输入只出现在 review 阶段画面中央的浅白 placeholder「加一句字幕」（`Views/Record/CameraComponents.swift:254-292`），用户拍完直接「使用这段」就永远不会遇到它；事后编辑藏在 ClipPreviewView 的「加字幕」chip（`ClipPreviewView.swift:330-348`）。
- **建议**：低优先。可在第一次进入 review 页时给 placeholder 一次短暂的呼吸动画，或在「使用这段」上方第一次出现时加一行淡提示。

## 旅程 6：回看与成片（时间线 → 影片 → 导出/分享）

### 6.1 ClipDeckReview 可以左右滑，但没有任何信号 🟡

- **现状**：`TabView` 翻页但 `.page(indexDisplayMode: .never)`（`Views/Record/ClipDeckReview.swift:60`），全黑背景、无页点、无边缘偷看。
- **问题**：从网格点开一个片段的用户，看到的是「一个片段 + 关闭按钮」，没有任何迹象表明左右滑能看其他瞬间。代码注释说这是核心改进（「three taps and two dissolves」的修复），但手势本身不可发现。
- **建议**：打开页点显示（`.page(indexDisplayMode: .automatic)`），页点放底部安全区内；或首次进入时底部浮一行「左右滑动看其他瞬间 · 3/7」，2 秒后淡出。

### 6.2 保存相册被拒后没有出口 🟡

- **现状**：`saveToPhotos` 被拒只显示一行文案「需要相册权限才能保存视频。」（`Views/Film/FilmView.swift:210-213`；文案 `Localization.swift:775-777`），没有「打开系统设置」按钮。
- **问题**：与通知权限被拒的处理不一致（Settings 里有「打开系统设置」，`SettingsView.swift:124-128`）。用户在成片页——情绪最高点——撞墙且没有路标。
- **建议**：`photosDenied` 时把 saveMessage 换成带按钮的条：文案 + 「打开设置」。复用现有模式，改动局限在 FilmView。

### 6.3 其余良好（记录为优点，不用改）

- 完成瞬间的庆祝 → 自动进入合成（`StoryTimelineView.swift:79-88`），无需发现任何按钮；
- `GeneratingFilm` 分步文案把等待变成内容（`Views/Film/GeneratingFilm.swift`）；
- 未完成时「预览影片」收进 ⋯ 菜单（`StoryTimelineView.swift:297-308`），取舍合理；
- Adjust sheet（标题卡/字幕/转场）是克制的纯表单，符合定位。

## 旅程 7：次日回归（提醒 → 继续 7 日故事）

### 7.1 「接着拍」的故事，按钮仍写「继续今天的故事」 🔵

- **现状**：hero 卡区标题会区分「今天的故事」/「接着拍」（`PlansHomeView.swift:227-243`，注释里明确说「把昨天的故事叫今天的故事是撒谎」），但 StoryCard 的按钮写死 `Strings.continueTodaysStory`（`Views/Components/StoryCard.swift:131-139`）。
- **问题**：同一屏上卡片说「接着拍」（昨天那个），按钮说「继续今天的故事」——自相矛盾，正是代码注释里立誓要避免的那种小谎。
- **建议**：StoryCard 增加一个 ctaLabel 参数，resume 状态下用「接着拍 · 还差 N 个」。

### 7.2 7 日挑战的 CTA 指向「最早空缺」而非「今天」 🔵

- **现状**：`slotToRecord` 取第一个没人拍的 slot（`PlansHomeView.swift:376-386`；`RoomProgress.nextOpenMoment`，`Presentation/RoomProgress.swift:66-69`）。漏拍第 2 天、今天第 4 天时，按钮直接开第 2 天的相机。
- **问题**：caption 有「还没拍：第 2 天」说明（`Strings.openMomentLabel`），不至于迷路；但「记录第 4 天却进了第 2 天」仍可能让按天推进的用户迟疑。代码注释表明这是房间场景下的刻意取舍（避免三个早餐、没有晚上）。
- **建议**：保持行为，卡片 caption 写得更明确：「先补第 2 天（今天第 4 天）」。低优先。

### 7.3 提醒链路（记录为优点）

- 晚间提醒 reconcile（`Services/ReminderService.swift`）、首次保存片段后弹 primer（`RecordClipView.swift:421-430`）、通知点按直达相机对应 slot（`PlansHomeView.swift:413-422`）——整条回归链路是通的。

## 跨旅程问题

### X.1 删除故事 / 退出房间没有任何二次确认 🔴

- **现状**：故事页 ⋯ 菜单的「删除挑战/退出房间」（`Views/Timeline/StoryTimelineView.swift:314-321`）和主页列表的长按菜单（`Views/Plans/PlansHomeView.swift:332-339`）都直接调 `store.delete`，后者连带删除全部片段文件（`Services/ChallengeStore.swift:382-389`，`fileStore.deleteClips`）。
- **问题**：一次误触 = 一个故事的全部片段永久删除，不可恢复。对比之下 `deleteAccount` 有完整的确认对话框和警告文案（`SettingsView.swift:237-253`）——app 自己最危险的高频操作反而裸奔。长按菜单尤其容易误触。
- **建议**：两处都加 `confirmationDialog`：「删除《标题》？N 段片段会一起删掉，无法恢复。」退出房间则区分文案：「退出后这台设备上看不到大家的片段，房间里你的片段保留给其他人」（如果语义如此，需在文案前与 CloudKit 行为核对）。按钮仍用 destructive。

## 建议落地顺序

1. **先做三个 🔴**（各是一个下午的改动）：5.1 丢片段、5.2 相机死路、X.1 无确认删除——都是「用户东西没了/功能打不开」级别。
2. **再做 4.1 + 4.2**：加入链路是裂变增长的生命线，且 4.1 的文案已经写好只差接上。
3. 2.1、4.4 是一行文案级改动，顺手做掉。
4. 其余 🟡/🔵 按主题打包（录制体验一批、加入/邀请一批、回归一批）。
